Техническое задание и условия приёмки

Записывай, что должно получиться на выходе, и проверяй результат в масштабе применения. Отделяй обязательные условия от художественных предпочтений. Чем меньше свободы у изображения по форме, маркировке и размещению, тем больше ценность зафиксированного исходника и ручного монтажа.

Уровень Пример для карточки кронштейна Способ проверки
Обязательно Два отверстия, прямой фланец, исходный силуэт Сверка с утверждённым рендером
Предпочтительно Мягкая тень, графитовая поверхность Просмотр карточки на светлой и тёмной теме
Свобода Положение слабого светового пятна Проверка контраста
За пределами генерации Размеры, допуски, марка материала CAD, КД и спецификация

Сохрани исходники, промпт, версию результата и итоговое решение. Когда работаешь в ChatGPT, фиксируй доступное название режима и дату, если внутренний ID модели неизвестен. За исходные файлы принимай версии, на которые у тебя есть право и доступ. Для клиентских материалов перед загрузкой проверь условия проекта и убери данные, которые не нужны задаче.

Генерация вокруг инженерного исходника

В качестве первого вложения дай собственный утверждённый рендер. При необходимости вторым приложи образец света и фона. Геометрия и КД живут в CAD. Изображение можно использовать для презентации, если визуальный результат сверили с исходником.

Задача — обложка кейса о листовом кронштейне.
Вложение 1 — утверждённый рендер детали. Сохрани контур, видимый гиб, два отверстия и ракурс. Вложение 2 — эталон освещения и фона, только для среды.
Размести деталь справа, освещение мягкое сверху слева. Оставь левую треть для текста. Без размеров и маркировки. Широкий кадр.

Приёмка. Проверь количество отверстий, контур гиба и кромки. Наложи картинку на исходный рендер при совпадающем масштабе. Если контуры разошлись, скомпонуй исходную деталь с отдельным сгенерированным фоном. Для контроля изменений чертежа сравни версии исходных PDF или CAD. Изменение размера на 1 мм проверь по размерному числу или непосредственно в модели.

Запасной сценарий. Попроси фон без предмета, с местом и светом под исходный рендер. Смонтируй деталь поверх, сохрани маску отдельным слоем.

Протокол локальной правки

  1. Сохрани утверждённую версию и дай ей понятное имя, например bracket-base-v03.png.
  2. Укажи область правки и перечисли защищённые детали.
  3. Сгенерируй правку от сохранённой версии. Сравни и прими её до следующего изменения.
  4. Если защищённые области должны совпасть попиксельно, перенеси нужный участок в оригинал обычным композитингом.
  5. Проверь итог на границе маски. Сверь на светлой и тёмной подложках ореолы, резкость и тени.
На выбранном кадре измени только заднюю стену справа от кронштейна. Сделай её матовой графитовой. Сохрани сам кронштейн, два отверстия, гиб, тень под деталью и весь передний план. Оставь кадрирование прежним.

Выделение в ChatGPT помогает показать область, но правка может распространиться за её границы. Для точного монтажа вычисляй разницу за пределами защищённой области на PNG одинаковых размеров. При допуске на перерисовку проверяй признаки по приёмке. Редактор ChatGPT · Приёмы редактирования OpenAI.

Текст, цвета и выпуск материалов

Для короткой надписи задай точные символы, положение и строку. После генерации сравни с утверждённой копией. Для точного фирменного цвета, артикула или схемы используй слои редактора с исходным логотипом и векторным текстом. Проверь фактические размеры файла, пропорции, альфа-канал и пригодность к печати.

Проверка Сигнал брака
100% масштаба Размытый контур, ореол или видимый шов
Размер публикации Деталь теряется, текст слишком мелкий
Сверка с референсом Иной цвет, пропавшая фаска, добавленный крепёж
Строки и символы Перепутаны 0 и O, 1 и I, Е и Ё
Файл Неверное соотношение сторон или сплошной фон вместо прозрачности
Право на публикацию В кадр попали чужой логотип, реквизиты или закрытые данные

Подготовь экспорт под конкретный канал. Для A4 с печатью сначала выясни требования к полям, вылетам и разрешению, затем проверь распечатку или PDF в целевом размере.

Серия изображений и сравнение версий

Для серии сначала утверди эталонный кадр. Опиши правила для объекта, ракурса, света, подложки и свободной зоны. Для каждой картинки сохраняй те же референсы и меняй только содержание нового сюжета. При заметном уходе стиля вернись к эталону и задай критичные ограничения заново.

Минимальный набор для проверки

Случай Приёмка
Предметный кадр Тот же контур, два отверстия, видны кромки
Локальная правка Новый фон, утверждённый объект сохранился
Короткий текст Все символы совпали и читаются в публикации
PNG с прозрачностью Есть прозрачные пиксели, чистые края

Сравни несколько запусков на одинаковых промптах и референсах. Меняй один параметр за раз. Запиши долю принятых картинок, время до готового результата и число повторов. Для API добавь стоимость всех попыток на один принятый файл. Единичная удача не показывает, насколько метод стабилен.

Приложение. Когда нужен API

В ChatGPT достаточно обычной команды. В автоматизированной сборке Image API подходит для разовых генераций и правок, Responses API для работы с изображениями в многошаговом диалоге. Доступ к модели и параметры проверяй для выбранного эндпоинта. Общий гайд и примеры могут описывать разные поколения. Руководство по Image API.

На дату сверки руководство по запросам описывает gpt-image-2.6-sunburst и gpt-image-2.6-flare. Для этой серии quality регулирует детализацию рендера, а complexity управляет глубиной планирования композиции. Для точечной правки сравни complexity=low с настройкой по умолчанию при фиксированном качестве. Модели и API-параметры сверяй перед каждым переносом примера. Параметры GPT Image.

Пример тела запроса для POST /v1/images/generations. Используй его только при наличии доступа к выбранной модели. Это пример для API, команды выше предназначены для чата.

{
  "model": "gpt-image-2.6-flare",
  "prompt": "Нейтральный фон для карточки товара. Светло-серая матовая поверхность, мягкий свет слева. Без объектов и текста.",
  "size": "1536x1024",
  "quality": "medium",
  "output_format": "png"
}

В рабочем контуре передавай ключ через окружение на сервере. В журнале храни ID модели, параметры, версию промпта и итог проверки. Не записывай ключ и клиентские вложения в общий лог. Обрабатывай временные ошибки ограниченным числом повторов. Ошибки доступа и параметров разбирай по ответу API до следующего вызова.
